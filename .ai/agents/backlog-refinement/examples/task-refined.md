## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement repository interfaces and local implementations for the core domain entities (Individual, Observation, GenealogyRecord). Each repository must expose standard CRUD operations, domain-specific queries (filter, search), and transaction-safe write semantics backed by Room DAOs.

This layer bridges the domain layer and the Room database — no business logic, only data access and mapping.
<!-- SECTION:DESCRIPTION:END -->

## Assumptions

- Room DAOs for each entity are already generated by M3 (Room Schema).
- Data repositories will be injected via manual dependency injection (no Hilt/Koin for MVP).
- All write operations run on a background dispatcher provided by the caller.

## Acceptance Criteria

<!-- AC:BEGIN -->
- [ ] #1 Repository interfaces defined for Individual, Observation, and Genealogy Record
- [ ] #2 Each repository exposes: getById, getAll, insert, update, delete
- [ ] #3 Filter and search operations are available on IndividualRepository (by name, official number, date range)
- [ ] #4 Writes are transaction-safe — a failed batch write rolls back all changes in that transaction
- [ ] #5 Repository implementations delegate to Room DAOs and map entities to domain models
- [ ] #6 Unit tests cover all CRUD operations and transaction rollback behavior
<!-- AC:END -->
